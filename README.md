# QnapSelfCare

QNAPでOMRON HEM-6232T（血圧計）とHBF-228T（体重体組成計）の測定履歴を管理します。0.3.7ではペアリング・取得失敗時の手動診断付き操作を追加します。0.3.6は過去のOMRON connect CSVの取込と、身長・年齢・目標を使う健康サポート、食事メモ、AI相談を追加します。0.3.5は検出したBluetooth機器を選ぶだけで、アドレスを入力せずに機器登録とペアリングを開始できます。0.3.4はHomeHubのComposeに独自設定があっても、保存先や機器の安全条件を確認しつつ共通Bluetooth構成へ移行できます。0.3.2の診断・定期バックアップ・破損時の保護と復旧も利用できます。0.3.1からのWebボタンによる自己更新も利用できます。0.3.0からの利用者・機器管理、記録の保存・編集、グラフ、CSV、バックアップとUSB Bluetooth収集も利用できます。0.3.1のWeb接続・バージョン表示は利用者のNASで確認済みです。**BLEペアリング・履歴同期は実機での検証が必要です。** ESP32は使用しません。

## 機能

- 利用者別の血圧・脈拍・体重・体組成履歴、期間フィルター、グラフ。血圧・BMIの個別設定可能な参考線。
- 同日の複数測定を保持し、身長に基づくBMI、身長・年齢・体重と計算条件から推定した基礎代謝、日平均による体重変化、目標の進捗と見直し通知。食事メモと保存した計画。
- ControlDeck（初期選択）・同じNASのQnapAssistant・その他のローカルOpenAI互換API・OpenRouterへの明示的なAI相談。回答から計画へコピーして確認後に保存。
- 手入力・修正・削除。削除・修正済みの元記録はBluetoothで再取得しても復活させません。
- HEM-6232Tの2人分・HBF-228Tの4人分の機器スロットを利用者へ割当。
- USB BLEのスキャン、明示的なペアリング、保存履歴読取、自動探索と同期。
- 初回起動時・7日ごとの検証済み完全バックアップ、14世代保存（間隔・世代数は変更可）。
- DB整合性・空き容量・保存先・バックアップ・Bluetoothの診断。破損時の保護モードと停止中の復元。
- SQLiteへの永続保存、測定時刻のUTC正規化と重複排除。
- QnapSelfCare形式のCSV取込・出力、JSONバックアップ・空の保存先への復元。
- GitHub Releaseの更新確認と「更新する」ボタン。NASがQPKG取得・SHA-256検証・DBバックアップ・適用・再起動確認まで実行します。

| サービス | 待ち受け | 役割 |
| --- | --- | --- |
| QnapSelfCare | `17863` | 健康記録の管理・表示・収集依頼 |
| QnapHomeHub | `8787` | SwitchBot・Matter連携の管理・操作依頼 |
| 共通radio | TCPポートなし | NAS内Unixソケットで依頼を受け、USB BLEを直列制御 |

QnapHomeHub 0.3.0のradioサービスとの共用が既定です。旧構成の場合は「設定・バックアップ → 共通Bluetoothのセットアップ → 共通Bluetooth構成へ更新」を押してください。設定を検証し、退避・適用・起動確認までNASが実行します。[移行と復旧の詳細](docs/homehub-migration.md)を参照してください。通常はSelfCare用BlueZを維持し、SwitchBot操作時だけNobleへ切り替えます。別のドングルを使う場合、またはHomeHubを使わない場合は直接接続も選べます。[USB Bluetooth導入・共存手順](docs/bluetooth-homehub.md)を参照してください。

## Web画面と起動

QPKGをApp Centerでインストール・有効化し、`http://<NASのIP>:17863/` を開きます。QPKGはIPv4全インターフェースで待ち受け、接続元サブネットを限定しません。TailscaleでNASのIPv4へ到達できる場合も同じポートです。認証を設けない構成のため、到達できる人は健康記録の閲覧・編集、SelfCareの更新、HomeHub構成の移行ができます。NASのアクセス設定で利用範囲を管理してください。

Python 3.8以降と既存の `/share/Container` 共有フォルダを使います。`python3-path` がPython3 QPKG、`/opt/bin/python3.11`、`/opt/bin/python3`などを探索します。特殊な場所は `SELFCARE_PYTHON` で指定できます。起動に `nohup` は不要です。Web・保存・CSV機能はPython標準ライブラリだけで動作します。共通radioを利用する場合、NAS本体へのBleakやBlueZの追加は不要です。

ログは `/share/Container/QnapSelfCare/logs/selfcare.log`、インストール先は次で確認できます。

```sh
/sbin/getcfg QnapSelfCare Install_Path -f /etc/config/qpkg.conf
```

最初に「設定・バックアップ」で利用者を追加します。手入力・CSV取込はすぐに利用できます。Bluetoothを使う場合は、共通radioの導入後に機器を登録し、利用者スロットを割当、ペアリング、手動同期の順で確認してから自動同期を有効にします。

## 保存とバックアップ

永続データの既定ルートは `/share/Container/QnapSelfCare` です。QPKG本体の更新とは別に保持します。

| パス | 内容 |
| --- | --- |
| `data/measurements.sqlite3` | 利用者、機器、記録、重複防止、操作結果、機器のアプリ側ペアリングキー |
| `config/` | ペアリング中の復旧用キー（非公開） |
| `ai/` | 相談先ごとのAPIキー（管理者用、JSONバックアップ・完全バックアップには含めない） |
| `backups/` | 検証済みZIP・定期保存設定・結果。ペアリングキーを含む管理者用 |
| `recovery/` | 復元前のDB・設定の退避先。自動削除しません |
| `database.*.json` / `restore.pending.json` | 初期化・保護・復元中断の検出 |
| `logs/selfcare.log` | サービスログ |
| HomeHub側 `data/bluetooth/` | 共通radioのBlueZ bonding情報 |

DB・設定は管理者用の権限で保存します。**0.3.2以降は起動時に初回バックアップを作成し、既定で7日ごと・14世代をNASに保存します。**「データ保護・定期バックアップ」で間隔・世代数、手動実行、保存世代の再検査・ダウンロードを管理できます。診断は「システム診断」で実行します。破損時の保護と復旧は [データ保護・復旧手順](docs/data-protection.md) を参照してください。同じNASの故障に備え、ZIPを別の機器にも保管してください。

WebのJSONバックアップには利用者・機器・全記録・削除履歴・健康設定・食事メモ・AI接続設定を含めますが、ペアリングキーとAIのAPIキーは含めません。復元後は再ペアリングし、自動同期を再度有効にします。復元時は既存データへ上書きせず、全内容の検証と保存を1トランザクションで実行します。ファイル上限32MB・記録100,000件です。完全バックアップZIPはDB内のペアリングキーとSelfCareのconfigを含みます。HomeHubのBlueZ bonding情報は含まないため、radioを停止してHomeHub側の `data/bluetooth/` を権限を保持して別途保存してください。

CSVは画面からテンプレートを取得できます。`measured_at` は `2026-09-25T07:30:00+09:00` のように時差を含めます。`kind` は `blood_pressure` または `body_composition`、利用者は画面で選択またはCSV内の `user_id` を使います。1回8MB・10,000件まで全行を検証し、エラーがあれば保存しません。この一般形式CSVの欄はOMRON connect固有のファイルとは別です。OMRONファイルは下記の「過去のOMRONデータを引き継ぐ」を使います。表計算での数式実行を避けるため、出力CSVの該当文字列には先頭のアポストロフィを付けます。

## Bluetoothのペアリング・取得を診断する（0.3.7）

ペアリング成功は履歴を読める保証ではありません。血圧計のペアリング失敗時は本体を -P- 表示にして「機器と同期 → 診断付きペアリング」を選びます。体組成計で測定した直後、通信可能な間に「診断付き同期」を選びます。通常の自動同期はそのままです。診断付き操作は接続・Omronサービス検出・通知購読・保存済みキーによる認証・履歴領域の読取・レコード解釈・DB保存のどこで失敗したかを「同期・操作履歴」に表示します。各機器内利用者番号ごとの有効・空・無効の記録件数、先頭2件の有効値と失敗した生データを限定して残します。ペアリングキーは診断結果に含めません。**測定値や一部の生データは健康情報**です。診断付き同期を実行する前に確認を求め、結果はNASの測定DB（最大200ジョブの履歴）と週次バックアップにも残ります。他人に見せる前に内容を確認してください。

共通Bluetoothサービスを使う場合、BluetoothワーカーはQnapHomeHubのradioイメージに含まれます。**HomeHub 0.3.1以降のradioとSelfCare 0.3.7の両方**へ更新してください。HomeHubが旧版でも通常同期は動きますが、段階別の診断情報は取得できません。HomeHubの更新時は稼働中のBluetooth処理が途切れないよう、radioの更新完了後に新たに測定して試してください。SelfCare直接接続の場合、専用BluetoothコンテナはQPKG更新後に `docker compose -f bluetooth/compose.yaml up -d --build` で再ビルドしてください。NAS実機での体組成計の通信結果を確認するまでは原因を断定できません。

## BLEの範囲

HEM-6232Tは血圧・脈拍、HBF-228Tは体重・体脂肪率・骨格筋率・BMI・基礎代謝・体年齢・内臓脂肪レベルを読み取ります。機器内の有効な記録のみを扱い、未設定スロットは収集しません。機器時計は設定したUTC時差で解釈します。機器の時計や測定履歴を消去・書換えする操作は実装していません。ペアリング時は接続用キーを登録します。

自動同期は、未待機の機器があると約10秒スキャンし、検出した登録機器だけに接続します。成功・失敗にかかわらず機器ごとの同期間隔を設けます。広告停止中やスマートフォンとの接続中は収集できません。保存可能な履歴件数、電波、旧QNAPカーネルとUSBドングルの互換性は実機に依存します。

機器登録は「機器と同期 → 近くのBluetooth機器を探して登録」から行います。ペアリングモード中の機器を10秒間スキャンし、検出結果から機器を選びます。HEM-6232T / HBF-228Tの型番が広告名で確認できる場合は自動選択し、識別できない名前なら型番を選択してください。利用者が1人なら自動割当され、機器内の番号は1番が初期値です。機器本体で別の番号を使う場合は選び直してください。登録後にペアリングを開始し、成功後は自動同期を有効にします。結果は「同期・操作履歴」で確認できます。実機での通信結果に応じて機種と利用者番号を調整してください。

設定・バックアップの「過去のOMRONデータを引き継ぐ」から、HEM-6232Tの血圧CSVまたはHBF-228Tの体組成CSVを指定できます。ファイルごとに利用者を選び、追加予定件数・重複件数・期間を確認してから反映します。日時はCSVのタイムゾーン（Asia/Tokyo等）を使い、血圧・脈拍・体重・体組成の対応列を測定記録に、追加の判定項目はメモに保存します。同日の別時刻・別の値は受け入れ、同一時刻・同一値だけ重複として扱います。既存の記録・機器設定は上書きしません。複数人の履歴が1つのCSVに混在する場合は利用者ごとに分けてから取り込んでください。1ファイル10,000件・8MBまでです。

## 健康サポートとAI相談（0.3.6以降）

「健康サポート」で利用者を選び、身長、年齢、基礎代謝推定式に用いる計算条件、目標体重・日付、血圧・BMIの参考上下限を保存します。BMIは身長と最新体重から計算し、基礎代謝は[Mifflin–St Jeor式](https://pubmed.ncbi.nlm.nih.gov/2305711/)による推定値です。機器の計測した基礎代謝とは別の値として表示します。初期参考線はBMI 18.5–24.9、家庭血圧の上限135/85、低血圧の参考90/60に基づく目安で、個人の診断基準ではありません。必要に応じ医療者の助言に合わせて変更してください。体重が7日以上離れた測定日にある場合は各日の平均の差を出し、目標までの週平均減量、14日間の記録空白、計画の30日経過などを画面表示時と記録更新時に確認します。バックグラウンドでAIへ定期送信はしません。

「設定・バックアップ → Qnap Assistant・ローカルLLMの設定」で接続先を選びます。初期選択はControlDeckで、**NASから到達できる** Ubuntu/Tailscale のアドレスを `http://<ホスト>:8765/api/v1/llm/v1` のように入力します。`localhost` はNAS自身です。ControlDeckが別のUbuntuにある場合はそのホスト名・IPを使い、必要なAPIキーを別欄に保存してください。QnapAssistantはNAS自身の `http://127.0.0.1:11435/v1` を使います。独自ローカルLLMはプライベートネットワーク上のOpenAI互換 `/v1` を設定します。OpenRouterだけは外部の `https://openrouter.ai/api/v1` とモデル名・APIキーを設定します。AIキーは `ai/` に権限を限定して保存し、JSON・週次ZIPバックアップには含めません。復元後は再入力してください。

AI相談では現在の体重・血圧・BMI・推定基礎代謝・変化・目標・保存計画（最大3,000文字）・最近5件の食事メモ・質問を送ります。毎回、送信先を確認するチェックが必要です。名前・利用者ID・全履歴・ペアリングキーは送信しません。回答は自動保存されず、「回答を計画欄にコピー」後、内容を編集して「健康設定・計画を保存」を押して反映します。AIの回答は診断や治療・薬の調整には使わず、気になる症状や継続する異常値は医療者へ相談してください。[QnapAssistant](https://github.com/souten-yd/QnapAssistant) は別サービスで、SelfCareのBluetooth・Webポートとは統合しません。

## Webからの自己更新（0.3.1以降）

0.3.1以降からは上記ボタンで0.3.7へ更新できます。0.3.0以前から今回版への切替だけはApp CenterでQPKGを手動適用してください。以後は「設定・バックアップ → SelfCareの更新 → 更新を確認 → vX.Y.Zに更新する」で、ブラウザへQPKGをダウンロードせず更新できます。

ボタンを押して確認すると、独立した更新ワーカーがNAS上で最新安定版を再確認し、CPUに合う公式リポジトリのQPKGを取得・SHA-256検証します。測定DBと設定をバックアップし、SelfCareを停止してQDKインストーラーを実行します。既存QPKGと同じボリュームに適用し、QPKG登録バージョンと新しいWebサービスの応答が一致してから完了と表示します。状態とログはNASに保存するので、Web再起動・画面再読み込み後も確認できます。nohupは不要です。

更新確認だけではインストールしません。定期自動適用は追加していません。ボタン連打はロックで拒否し、APIでは任意のURL・コマンドを受け付けません。QNAPの管理者権限、QPKG登録先・実行中バージョンの一致、空き容量が必要です。開発用の直接起動では適用ボタンを無効にします。

更新データは `/share/Container/QnapSelfCare/updates/` に置きます。

| パス | 内容 |
| --- | --- |
| `status.json` | 最後の更新状態・対象版・結果 |
| `<ジョブID>/update.log` | 更新・インストーラーのログ（画面では末尾を表示） |
| `<ジョブID>/backup/` | 更新直前のSQLite DBとconfig。ペアリングキーを含む管理者用バックアップ |

検証不一致・バックアップ失敗・サービス停止失敗ならQPKGを実行しません。QDKの終了コード0/10を受けた後も、登録版とWebの確認が必要です。適用の終了コードまたは起動確認が失敗した場合はエラーを保持し、有効なSelfCareの起動を試みます。インストーラーが10分経っても終了しない場合は途中で強制終了せず、実プロセスが終了するまで再実行を拒否します。ダウンロード・バックアップ・起動確認にも時間上限があります。中断後の自動再実行や、DBを巻き戻す自動ロールバックは行いません。

更新失敗後にWebへ接続できない場合はApp CenterでSelfCareの状態を確認し、必要なら同じ正式QPKGを手動再適用してください。ログ・バックアップと元の永続データは残ります。バックアップは自動削除しないため、必要に応じて保管・整理してください。

このボタンの対象はSelfCare QPKGです。HomeHubと共通radioはHomeHub側の更新機能で管理します。SelfCare専用BLEコンテナを使う場合は、従来どおり同梱Composeから再ビルドします。QNAP実機での自己更新は未検証で、CIではインストーラー境界を置き換えてライフサイクル・異常系を検証しています。

## 開発・CLI

```sh
python3 -m unittest discover -s tests -v
npm ci
npm test
python3 webapp.py --port 17863 --data-dir /tmp/selfcare-dev
```

開発起動はloopback待ち受けです。`--lan` で全IPv4インターフェースを使用します。CIはPython・DOM操作テストとQDKのx86_64 / arm_64ビルドを行います。実機BLE・NASのコンテナ起動はCIの対象外です。

```sh
./selfcare-update check --current-version 0.3.7 --arch x86_64
./selfcare-update download --current-version 0.3.7 --arch x86_64 --dest /path/to/private/staging
```

上記CLIのdownloadは検証付き取得専用です。通常の適用にはWebの更新ボタンを使います。配布名は `QnapSelfCare_X.Y.Z_<arch>.qpkg` です。GitHubが返すSHA-256 digestとダウンロードを照合し、不一致・digest欠落時は取得を完了しません。

BLEのプロトコル実装・第三者コードの出典と配布条件は [THIRD_PARTY.md](THIRD_PARTY.md) に記載しています。
