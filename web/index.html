USB BLUETOOTH
機器と同期
HEM-6232T・HBF-228TをUSB Bluetoothで接続します。ESP32は使用しません。
共通Bluetoothサービスを選ぶとHomeHubと同じドングルを順番に使えます。SelfCareを中心に管理し、HomeHubの操作時だけ一時的に切り替えます。直接接続は専用ドングル向けです。
近くのBluetooth機器を探して登録
先に利用者を追加し、機器をペアリングモードにしてください。血圧計は「-P-」表示を目安にします。検出した機器を選べばMACアドレスの入力は不要です。機種を特定できないときだけ選択してください。機器の利用者番号は初期値1番です。
血圧計のペアリング失敗時は -P- 表示中に「診断付きペアリング」、体組成計の取得失敗時は測定直後に「診断付き同期」を実行してください。診断結果には測定値や一部の生データが含まれ、NAS内の操作履歴・バックアップに保存されます。共有する前に内容を確認してください。共通BluetoothサービスではQnapHomeHubの対応版も必要です。

USB Bluetoothのセットアップ
HomeHubと共用する場合は、まず「設定・バックアップ → 共通Bluetoothのセットアップ」の移行ボタンを使ってください。以下はSSHで手動移行する場合の手順です。初回は旧HomeHubを docker compose stop homehub で停止し、QnapHomeHub 0.3.0以降のcompose.yamlへ移行後、docker compose pull と docker compose up -d radio homehub updater を実行します。同梱READMEの移行手順に従ってください。管理画面のポートはSelfCare 17863 / HomeHub 8787のままです。両者はNAS内のUnixソケットで通信します。
HomeHubを使わず、NASのネイティブBlueZが使える場合は同梱の scripts/install-ble.sh でPython依存を導入します。QNAPにBlueZがない場合は、QPKGに同梱したBluetooth用コンテナを起動してください。
cd "$(/sbin/getcfg QnapSelfCare Install_Path -f /etc/config/qpkg.conf)"
docker compose -f bluetooth/compose.yaml up -d --build
Container StationのDocker CLIにPATHが通っているSSHセッションで実行します。専用ドングルを使うか、共用中のHomeHubを先に停止してください。既存HomeHubの設定は自動変更しません。
初回は機器をペアリングモード（血圧計は「-P-」表示）にして「ペアリング」を押します。スマートフォンと機器の同時接続は避けてください。その後「履歴を同期」を実行します。機器が通信可能な間にのみ同期できます。
QPKG更新後は同じコマンドでコンテナも再ビルドしてください。詳しくは同梱README・USB Bluetooth手順を参照してください。

設定・バックアップ


データ保護・定期バックアップ


測定記録・利用者・機器・ペアリングキーをNASに保存します。作成後にDBの整合性とSHA-256を検証してから保存世代を確定します。













同じNASへの保存だけでは、NAS・ディスク全体の故障には備えられません。保存世代をダウンロードし、別の機器にも保管してください。ファイルには健康記録とペアリングキーが含まれます。




完全バックアップからの復旧
復元はSelfCareを停止してSSHから行います。現在のDB・設定は退避して保持します。途中で中断した場合も空のDBを新規作成しません。同じ復元コマンドを再実行できます。
下記の「保存したファイル.zip」を、一覧の保存先にあるファイルまたはNASへ戻したダウンロードファイルの絶対パスに置き換えてください。
cd "$(/sbin/getcfg QnapSelfCare Install_Path -f /etc/config/qpkg.conf)"
./selfcare-backup verify "/保存したファイル.zip"
./selfcare.sh stop
./selfcare-backup restore "/保存したファイル.zip" --confirm-replace
./selfcare.sh start
復元が成功したことを確認してから起動してください。復元後の自動同期はOFFです。共通radioのBlueZ情報はHomeHub側で別途保管してください。


Qnap Assistant・ローカルLLMの設定
初期選択はControlDeckのローカルLLMです。NASから届くControlDeckのホスト名とポートを設定してください。QnapAssistantは同じNASの11435番を使用します。OpenRouterを選ぶと相談時の健康情報が外部へ送られます。
接続確認では健康記録を送らず短い回答を求めます。相談・接続確認はモデル起動を含め最大5分待ちます。
キーはNAS内で別管理します。JSONの引き継ぎには含まれないため復元後は再入力してください。

過去のOMRONデータを引き継ぐ
OMRON connectから出力した「測定日・タイムゾーン・機種」列がある血圧計 HEM-6232T / 体組成計 HBF-228T のCSVを取り込みます。血圧と体重は別ファイルで選択してください。1ファイルの全記録を同じ利用者に割り当てます。
MACアドレスや機器のペアリング設定は不要です。元CSVの測定日時と数値を確認して反映します。既存記録は上書きしません。1ファイル10,000件・8MBまで。
CSVの取込
QnapSelfCare形式のCSVに対応します。測定日時にはタイムゾーンを含めてください。空のテンプレート
1回10,000件・8MBまで。全行を検証し、不正な行があると保存しません。重複は追加しません。
JSON出力・空の保存先への取込
利用者・機器設定・測定記録をJSONで保存します。Bluetoothのペアリングキーは含めません。

復元先に利用者や機器がある場合は上書きしません。復元後は再ペアリングし、自動同期を必要に応じて有効にしてください。32MBまで。

HomeHubの旧構成を、新しい共通Bluetooth構成へ更新します。HomeHubは一時停止します。設定を退避し、起動確認に失敗した場合は元の構成へ戻します。
移行中はNAS・SelfCareを停止しないでください。設定を変更した独自Composeは自動で上書きしません。
