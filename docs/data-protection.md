# データ保護と復旧（0.3.2以降）

「設定・バックアップ」に定期保存・世代一覧・診断を追加しました。既存のJSON入出力と自己更新も使用できます。

## 保存の動作

| 項目 | 動作 |
| --- | --- |
| 初期設定 | 有効、7日ごと（週1回）、14世代 |
| 保存間隔 | 6 / 12 / 24 / 168時間から選択。成功した保存時刻を基準に計算 |
| 初回・停止後 | 保存世代がない場合は起動後に実行。期限超過なら再起動後に1回実行 |
| 世代管理 | 手動・定期を合わせて2〜90世代。新規保存に成功した後だけ古い正常世代を削除 |
| 失敗 | エラーを画面へ表示。過去のバックアップを保持し、自動再試行は最短1時間後 |
| 停止中 | NAS/SelfCare停止中は実行しません。画面を閉じても稼働中は保存します |
| 既定の保存先 | `/share/Container/QnapSelfCare/backups/` |
| 保存範囲 | 利用者・機器・全測定記録・削除済み記録の再取込防止情報・ジョブ・アプリ側ペアリングキー・config内のペアリング復旧用キー |
| 別途保存するもの | HomeHubのBlueZ bonding情報、アプリ本体、ログ、定期保存の設定 |

SQLiteのオンラインバックアップAPIで、稼働中のWALを含む確定済みデータを取得します。DBファイルだけを通常コピーする方法は使用しません。復元用コピーに対し `integrity_check`、`foreign_key_check`、必須テーブル・列・JSON形式、記録件数を確認します。ZIPを作成し、格納ファイルを再展開してSHA-256とDBを再検証し、ファイル同期後に完成ファイルへ切り替えます。途中のファイルは保存世代として扱いません。

バックアップはディレクトリ700、ファイル600で保存します。健康記録・秘密鍵を含み、暗号化ZIPではありません。NAS外へ保存する場合もアクセス権を管理してください。同じNAS内のバックアップではNAS・ボリューム全体の故障は防げません。「検証してダウンロード」から別の機器にも保存してください。

バックアップは展開後合計2GBまでです。作成時はDB/WALサイズの4倍＋64MiBを空き容量の目安として事前確認します。検証失敗した世代・未知のファイルは自動削除しないため、保持数を超える場合があります。自己更新時の `updates/<ID>/backup/` と復元時の `recovery/` はこの世代整理の対象外です。

## 診断

「診断を更新」はDBの整合性・参照関係、保存先の書き込みと同期、空き容量、バックアップの実施状況、収集ワーカー、共通radioへの接続を確認します。DB検査は10秒で打ち切り、負荷・ロック等で検査できない場合はエラーを表示します。検査タイムアウトや空き容量不足だけでDBを破損扱いにはしません。

「最新バックアップを検査」は保存済みの最新世代を背景で再検証します。ZIP内のSHA-256・整合性・件数を確認し、結果を保持します。ブラウザを閉じても処理は継続します。ダウンロード・復元時にも毎回検証します。チェックサムは偶発的な変化の検出用で、作成者を認証する電子署名ではありません。

共通radioを選択しているのにソケットへ接続できない場合は「未接続」と表示します。NAS本体のPython BLE未導入・D-Bus未検出を共通radioの必須条件として扱いません。HomeHub 0.3.0以降のradio稼働・ソケット共有・権限を確認してください。診断はUSBをリセットせず、Bluetoothサービスの起動停止も行いません。

## 破損時の保護

起動時、診断時、バックアップ時、通常の保存処理で破損を検出すると、以後のDBアクセス・新規収集依頼を止めます。すでに実行中の外部BLE操作は完了する場合がありますが、保護後はDBへ保存しません。Webの診断、バックアップ一覧・検査・取得は使用できます。保護状態はDB外に保持し、DB消失・0バイト化を空のDBとして初期化しません。

SQLite整合性検査は論理的に正しい値への意図しない変更まで判別できません。定期バックアップの保存間隔内の変更は、直前世代へ復元すると失われます。必要な時点で手動保存し、複数世代を保管してください。

## 完全バックアップから復元

NASのSSHで実行します。WebにあるJSON復元は空の保存先への取込専用です。完全ZIPの復元は、SelfCare停止中に専用コマンドを使用します。

```sh
cd "$(/sbin/getcfg QnapSelfCare Install_Path -f /etc/config/qpkg.conf)"
./selfcare-backup verify "/share/Container/QnapSelfCare/backups/保存世代のファイル名.zip"
./selfcare.sh stop
./selfcare-backup restore "/share/Container/QnapSelfCare/backups/保存世代のファイル名.zip" --confirm-replace
```

**復元が完了した表示を確認してから**起動してください。

```sh
./selfcare.sh start
```

独自の保存先では `./selfcare-backup --data-dir /保存先 restore /バックアップ.zip --confirm-replace` のように指定します。取得ファイルをNASへ戻して使用する場合も絶対パスで指定してください。

サービス・更新ワーカーが動作している間はロックで復元を拒否します。復元用ZIPを検証してから、現在の `data/` と `config/` を `recovery/<日時-ID>/` へ退避し、検証済みDB・設定に置き換えます。退避には破損したDBと残っているWAL/SHMも含みます。自動削除しません。復元後の自動同期はOFFになり、利用者・機器・記録・ペアリングを確認してから再度有効にします。

電源断などで復元が中断した場合は、次回起動も保護モードになります。停止して同じ検証済みZIPから復元コマンドを再実行してください。以前の退避データも保持します。`database.guard.json`、`restore.pending.json` やDBを手動削除して初期化しないでください。

HomeHub側のBlueZ情報を失った場合は、HomeHubバックアップから復元するか再ペアリングが必要です。SelfCareだけの復元では共通radioの状態は変更しません。

この版はローカル・CIで実DBの破損・容量不足・検証不一致・中断を再現しています。NAS実機でのバックアップ・復旧操作とBLE連携は別途確認が必要です。

実装の根拠: [SQLite Online Backup API](https://www.sqlite.org/backup.html)、[SQLite PRAGMA](https://www.sqlite.org/pragma.html)。
