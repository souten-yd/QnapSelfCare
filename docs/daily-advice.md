# 毎日のアドバイス（自動作成）

NAS上のQnapSelfCareが、毎日決まった時刻にその日の記録を直前7日間と比べ、AIから生活・減量のアドバイスを受け取ります。時刻やAIの接続先は設定の「AI」タブ、結果・相談・稼働状況は健康サポートの「AI」タブにあります。

## 動き

1. 1分ごとに時刻だけを確認します（設定はメモリにキャッシュし、ディスクを起こしません）。
2. 設定時刻（初期値 **2:00**）を過ぎたら、その日の分がまだない利用者ごとに作成します。
   - 12時より前の時刻は **前日分**、12時以降は **当日分** を評価します。
   - NASが止まっていた場合は、予定時刻から6時間以内なら起動後に作成します。
3. まず記録の比較（AIなし）を作ります：歩数・活動エネルギー・運動時間・睡眠時間・摂取・収支・体重・最高血圧を、直前7日の平均と比べて「いつもどおり／多め／少なめ」を判定します。
4. 比較結果・評価指標・計画などを添えて、AIに「1日の振り返りと翌日のアドバイス」を依頼します。回答は「要点／根拠になったデータ／提案（最大3つ）／注意」の形です。
5. 結果は利用者・日付ごとにDBへ保存し、健康サポート（AIタブ）とHomeに表示します。

## AIへの送り方

| 接続先 | 方式 |
|---|---|
| QnapAssistant | 非同期ジョブAPI（`/api/llm/jobs`）。15秒ごとに状態を確認し、最大45分待ちます（初期設定のモデル読込10分＋生成30分に余裕を加えた値）。 |
| ControlDeck・その他のローカルLLM | 従来の同期API（最大300秒）。 |
| OpenRouter（外部） | 「外部サービスにも自動で送信する」をオンにした場合だけ送ります。オフのときは記録の比較だけを作成します。 |

## 送らない・やり直す条件

- その日の記録が1つもない → 作成しません（AIにも送りません）。
- AIの接続先が未設定 → 記録の比較だけを保存します。
- AIが他の相談を処理中・混雑（429） → 10分後に再試行します（最大3回）。
- QnapAssistantの再起動などでジョブが失われた → 失敗として記録し、自動で再送はしません（QnapAssistantの方針に合わせています）。「昨日分を今すぐ作成」で作り直せます。
- SelfCareの再起動で作成中だったもの → 失敗として記録します。

## QnapAssistant側の変更

不要です。既存の非同期ジョブAPI（v0.5.9以降）で、受付・状態確認・結果取得・キャンセルの必要な機能がそろっています。1件ずつ順番に処理するため、待ち行列の上限（実行中1件＋待機4件）を超えません。

## API

- `GET /api/ai/daily-settings` / `POST /api/ai/daily-settings` `{enabled, time: "HH:MM", allow_external}`
- `GET /api/wellness/advice?user_id=` → 最新と直近14件
- `POST /api/wellness/advice/run` `{user_id, day: "yesterday" | "today"}` → 202（バックグラウンドで作成）

設定はJSONバックアップに含まれます。作成済みのアドバイスは再作成できるため、JSONバックアップには含めません（定期バックアップのDBには含まれます）。

## AI処理のバックグラウンド実行（300秒制限の解消）

以前は「計画のAI分析」「AIカロリー試算」「接続テスト」が同期API（最大300秒）で、QnapAssistantのモデル読込＋生成が300秒を超えるとエラーになっていました。現在はすべてのAI処理をSelfCare内のバックグラウンド処理として実行します。

1. ブラウザは `POST /api/ai/jobs`（`kind`: `consult` / `meal` / `test`）で依頼し、IDを受け取ります。
2. `GET /api/ai/jobs/status?id=` を数秒ごとに確認します（順番待ち・モデル読込中・生成中・経過時間・空きRAM）。画面を閉じても処理は続き、再読み込みすると相談の続きを表示します。
3. QnapAssistantは非同期ジョブAPIで最大45分待ちます。ほかの接続先は従来の同期API（最大300秒）です。
4. AI処理（相談・夜間のアドバイス・計画の点検）は1件ずつ順番に実行し、NASのモデルを取り合いません。
5. 処理内容（質問・回答）はメモリにだけ保持し、完了30分後に破棄します。`POST /api/ai/jobs/cancel` で中止できます。

## 減量計画の点検と修正案（同意して適用）

夜間のアドバイスのあとに、減量計画の点検も行います（週1回まで。新しい計画は14日間は点検しません）。「今すぐ点検する」で手動でも実行できます。

**見直しが必要と判断する条件**：計画線より0.5kg以上重い／今のペースで目標日に間に合わない／減量ペースが速すぎる・増加している／直近3週が横ばい／逆算した摂取量が安全な下限を下回る／目標日を過ぎた。

**修正案**（同じエネルギーモデルで目標日の体重を試算）：
- 案A 目標日を見直す：今の生活のまま、安全なペース（観測ペースが週0.25〜1.0%ならそのペース、そうでなければ0.5%）で目標日を再設定。
- 案B 摂取量を見直す：目標日はそのまま、必要な標準摂取量に変更。安全な下限（1200kcalと推定基礎代謝の高い方）を下回る、または週1%を超える場合は出しません。
- 案C 運動を増やす：目標日と摂取はそのまま、速歩相当（4.3 MET）の運動を1日30分追加。

目標日に1kg以上届かない案、目標がBMI下限を下回る場合には注意を表示します。AIが理由とトレードオフを説明し、1つを推奨します（AIがない場合は規則で推奨）。

**計画は自動では変わりません。** 「この案で計画を更新」を押し、確認ダイアログで同意したときだけ、新しい計画として保存します（理由つきで履歴に残り、元の計画も残ります）。案を作った後に手動で計画を変えた場合、その案は無効になります。

## AIの稼働状況（止まっているか・進んでいるかの確認）

AIは1件ずつ順番に動きます。健康サポート →「AI」タブの「AIの稼働状況」で、いま何が動いているかを確認できます。

| 表示 | 意味 |
|---|---|
| 実行中 | AIを使っている処理（例：毎日のアドバイス（利用者・日付）、AI相談、接続テスト）。夜間の自動処理には「（自動）」と付きます |
| 段階 | 順番待ち／モデルを読み込み中／回答を生成中と、その経過時間 |
| QnapAssistantの最終応答 | SelfCareが最後にQnapAssistantから状態を受け取ってからの時間。正常ならおおむね15秒以内で更新されます |
| 自動打ち切りまで | 開始から45分で必ず打ち切り、次の処理に進みます |

- **進んでいる**：「最終応答」が数秒〜十数秒前で、段階が「読み込み中→生成中」と進む。
- **止まっている可能性**：「最終応答」が3分を超えると警告を表示します（NASやQnapAssistantの停止・再起動など）。待っても45分で自動的に打ち切ります。すぐ止めるには「実行中の処理を中止」（QnapAssistant側の処理も取り消します）。
- 待っている依頼には「〇〇の完了を待っています（その処理は△△・経過時間）」と、何を待っているかを表示します。画面からの依頼は60分待っても空かない場合に取り消します。
- 画面からの依頼は夜間の自動処理より優先します（夜間処理は利用者ごとの区切りで順番を譲ります）。手動の「昨日分を今すぐ作成」「今すぐ点検する」も画面からの依頼として扱います。

## 予定時刻を過ぎた場合の取り戻し

NASが止まっていた・更新で再起動した等で予定時刻（初期値2:00）に動けなかった場合、**予定時刻から6時間以内**なら起動後に作成します。6時間を過ぎていた場合（例：19時に更新した）は、日中に重いAI処理を始めないよう自動作成を見送り、「予定時刻を大きく過ぎたため自動作成を見送り」と表示します。「昨日分を今すぐ作成」で手動作成できます。

## 設定の場所

- **設定 →「AI」タブ**：AIの接続先・APIキー・接続テスト、毎日のアドバイスの自動作成と時刻。
- **健康サポート →「AI」タブ**：AIの稼働状況、毎日のアドバイス（結果・手動作成・履歴）、AI相談。
- メインメニューの順番：ホーム → 健康 → 記録 → 機器 → 設定。
