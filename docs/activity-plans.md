# 活動記録と週次の減量計画（0.3.15）

「健康」で身体情報を保存し、「日々の活動を入力・修正」と「週次の減量計画」を使います。

- 活動記録は利用者・日本時間の日付ごとに1件。同じ日の保存で修正できます。歩数・運動時間・活動係数・総消費・総摂取・その日の摂取目標・メモを記録できます。未入力と0を区別します。
- 活動係数は1日全体の活動を表す目安です。歩数や運動時間から消費を追加加算しません。総消費入力は推定総消費を置換します。スマートウォッチの「アクティブカロリー」だけを入れないでください。
- 1日総摂取は1日分の合計です。食事メモは一部の食事しか記録されない場合があるため自動加算しません。収支は総摂取−総消費（負なら消費が多い）です。
- 同日の複数体重は日平均にし、各日の平均を同じ重みで週平均にします。計画開始日から7日単位。週末（途中の週は今日）の直線的な計画体重と比較し、実測−計画と実測−目標を表示します。欠測週は空欄で、0や補間した実測を作りません。
- 新しい計画の保存で修正履歴を残します。日付・開始体重・目標体重・目標日・活動係数・摂取設定・追加低下の仮定・理由を保持します。週次表示は最新計画、以前の計画は「修正履歴」で確認できます。目標は身体情報にも反映され、以後の目標変更は週次計画から行います。
- 最新の体重を基準に推定代謝と総消費を再計算。履歴は当日以前で最後に測定した体重を使い、未来の体重を過去に当てはめません。身長・年齢・計算条件は現在の設定で再計算します。体重の基準日を表示し、実測基礎代謝とは区別します。
- 直近3つの完了週で各3日以上測定し、最初と最後の週平均の減少が0.2kg未満なら見直し通知を出します。代謝低下の診断や自動的な摂取削減は行いません。
- 活動・計画履歴はSQLite完全バックアップとJSON引き継ぎに含まれます。旧JSONは新項目なしでも復元可能です。AI相談は直近7件の活動と4週分の進捗・現在の計画を含みます。AI回答で数値目標を自動上書きしません。

## 推定式と限界

既存のMifflin–St Jeor式（厳密には安静時消費エネルギーの推定）を使い、UIでは既存名称「推定基礎代謝」を継続します。総消費はこれに活動係数を掛けた簡易推定です。

- 原論文: https://pubmed.ncbi.nlm.nih.gov/2305711/
- 体重変化に伴う必要エネルギーの変化について: https://www.niddk.nih.gov/research-funding/at-niddk/labs-branches/laboratory-biological-modeling/integrative-physiology-section/research/body-weight-planner

試算は毎日、体重に応じて代謝と消費を再計算し、エネルギー収支/7700で体重を更新します。固定摂取なら体重低下とともに消費差が縮みます。追加の消費低下はユーザー指定0〜15%が8週間で線形に生じる感度分析です。初期値0%で、実測から推定した代謝適応率ではありません。NIHの検証済み動的モデルの実装ではなく、水分や体組成変化を扱わない簡易シナリオです。

消費との差で自動設定する目標が1200kcalまたは推定基礎代謝を下回る場合、現在の目標の提示を止め、見直しを表示します。試算では同じ下限を使います。固定摂取入力は明示的に優先し、基礎代謝未満なら注意を表示。これらの値は安全性や減量結果を保証しません。目標日までの直線的な計画と、消費変化を含む試算は別の線で表示します。

## いつもの活動・摂取量（0.3.18）

活動フォームの初期選択は「今日からいつもの設定にする」です。日付別の入力と同時に、今日以降の未入力日に使う設定を保存します。PAL・歩数・運動時間・総摂取・任意の固定総消費／摂取目標・メモを再利用します。総摂取は朝昼晩・間食を含む1日合計で、食事メモを自動合算しません。過去の食事メモは「同じ内容を入力」から再利用できます。

例外日は「この日だけ変更」で保存し、翌日はいつもの設定に戻ります。その日の入力がある場合は全項目で優先します（空欄もそのまま）。その日の入力を削除すると、適用可能な設定値に戻ります。「使い回しを停止」は今日以降への適用を停止し、以前の日や個別入力を削除しません。

更新前に保存した活動は「前回の入力を使う」で読み込み、いつもの設定として保存できます。過去日の入力を編集するときも、いつもの設定の変更は今日からです。設定変更は適用日付きで保持し、過去日を新しい設定で書き換えません。同じ日の設定変更は、その日以降の未入力日の仮定を更新します。

未入力の日の使い回しは日次実績レコードとして自動挿入せず、グラフで「いつもの設定」と区別します。基礎代謝は日付時点までの体重で再計算し、固定総消費を入力していなければ、同じ活動係数でも消費量は変化します。AIにも仮定であることを伝えます。通常設定・変更・停止履歴を完全バックアップとJSONに含めます。旧JSONも引き続き復元できます。


## 標準モデル・計画差・AI支援（0.3.19）

週次の減量計画は、毎日の入力を前提にせず「普段こうする」という標準モデルを保存できます。身体情報と開始体重から推定安静時消費を計算し、意図的な運動を除く生活活動係数と、標準運動の時間・METを組み合わせて開始時の総消費を概算します。標準摂取を入力した場合はその値を優先し、空欄なら総消費から指定した差を引きます。

標準運動は MET の一般式 `MET × 3.5 × 体重kg / 200 × 分` を基礎にし、生活活動側で安静時消費を既に含むため、計画では `max(MET - 1, 0)` の正味分だけを追加します。METは個人ごとの精密な消費測定ではなく、活動強度を標準化した目安です。

「目標の計画線」は開始体重と目標体重を直線で結ぶ比較線です。「代謝変化を含む試算」は、体重が変わるたび推定安静時消費・標準運動消費を更新し、標準摂取と追加消費低下の感度設定を使って日次で進める簡易シナリオです。2本の線が一致することは保証されません。試算が目標日に届かない場合は、目標日の試算体重、目標との差、目標までに単純逆算した平均エネルギー差を画面に表示します。

自動計算の摂取量は従来どおり1200 kcal/日と推定基礎代謝の高い方を下限として扱います。目標日から逆算した摂取量がこの下限を下回る場合、その値を自動目標にせず、期間・生活活動・標準運動を含めた見直しを表示します。この下限は個人の安全を保証する処方値ではありません。

グラフ横の説明アイコンで2本の線の意味を確認できます。「AIで達成方法を分析」は、保存済みの計画、試算差、直近の週次実績を既存のAI相談先へ送り、目標日の延長・標準摂取・生活活動・標準運動という複数の調整候補とトレードオフを整理します。AIが数値を自動保存することはありません。

活動量とエネルギーには「朝食・昼食・夕食からAIで摂取カロリーを試算」を追加しました。食事文章だけを設定済みAIへ送り、総摂取と内訳・前提を構造化して受け取ります。接続先自体にWeb検索機能がある場合だけ、そのAIへ公開情報の参照を依頼します。QnapSelfCare自身が任意のWebサイトへアクセスする機能は追加しません。AI試算は自動保存せず、利用者が確認して「その日の摂取」または「標準摂取」欄へ反映し、その後に保存します。
