# 活動記録と週次の減量計画（0.3.15）

「健康」で身体情報を保存し、「日々の活動を入力・修正」と「週次の減量計画」を使います。

- 活動記録は利用者・日本時間の日付ごとに1件。同じ日の保存で修正できます。歩数・運動時間・活動係数・総消費・総摂取・その日の摂取目標・メモを記録できます。未入力と0を区別します。
- 活動係数は1日全体の活動を表す目安です。歩数や運動時間から消費を追加加算しません。総消費入力は推定総消費を置換します。スマートウォッチの「アクティブカロリー」だけを入れないでください。
- 1日総摂取は1日分の合計です。食事メモは一部の食事しか記録されない場合があるため自動加算しません。収支は総摂取−総消費（負なら消費が多い）です。
- 同日の複数体重は日平均にし、各日の平均を同じ重みで週平均にします。計画開始日から7日単位。週末（途中の週は今日）の直線的な計画体重と比較し、実測−計画と実測−目標を表示します。欠測週は空欄で、0や補間した実測を作りません。
- 新しい計画の保存で修正履歴を残します。日付・開始体重・目標体重・目標日・活動係数・摂取設定・追加低下の仮定・理由を保持します。週次表示は最新計画、以前の計画は「修正履歴」で確認できます。目標は身体情報にも反映され、以後の目標変更は週次計画から行います。
- 最新の体重を基準に推定代謝と総消費を再計算。履歴は当日以前で最後に測定した体重を使い、未来の体重を過去に当てはめません。身長・年齢・計算条件は現在の設定で再計算します。体重の基準日を表示し、実測基礎代謝とは区別します。
- 直近3つの完了週で各3日以上測定し、最初と最後の週平均の減少が0.2kg未満なら見直し通知を出します。代謝低下の診断や自動的な摂取削減は行いません。
- 活動・計画履歴はSQLite完全バックアップとJSON引き継ぎに含まれます。旧JSONは新項目なしでも復元可能です。AI相談は直近7件の活動と4週分の進捗・現在の計画を含みます。AI回答で数値目標を自動上書きしません。

## 推定式と限界

既存のMifflin–St Jeor式（厳密には安静時消費エネルギーの推定）を使い、UIでは既存名称「推定基礎代謝」を継続します。総消費はこれに活動係数を掛けた簡易推定です。

- 原論文: https://pubmed.ncbi.nlm.nih.gov/2305711/
- 体重変化に伴う必要エネルギーの変化について: https://www.niddk.nih.gov/research-funding/at-niddk/labs-branches/laboratory-biological-modeling/integrative-physiology-section/research/body-weight-planner

試算は毎日、体重に応じて代謝と消費を再計算し、エネルギー収支/7700で体重を更新します。固定摂取なら体重低下とともに消費差が縮みます。追加の消費低下はユーザー指定0〜15%が8週間で線形に生じる感度分析です。初期値0%で、実測から推定した代謝適応率ではありません。NIHの検証済み動的モデルの実装ではなく、水分や体組成変化を扱わない簡易シナリオです。

消費との差で自動設定する目標が1200kcalまたは推定基礎代謝を下回る場合、現在の目標の提示を止め、見直しを表示します。試算では同じ下限を使います。固定摂取入力は明示的に優先し、基礎代謝未満なら注意を表示。これらの値は安全性や減量結果を保証しません。目標日までの直線的な計画と、消費変化を含む試算は別の線で表示します。
