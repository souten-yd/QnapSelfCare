# Home（ダッシュボード）画面の再設計

## 1. 現状の表示内容チェック

| 区画 | 表示内容 | 課題 |
|---|---|---|
| ヒーロー | キャッチコピー「毎日の変化を、見える記録に。」とアイコン | 毎日開いても情報がなく、画面の最上部を占有している |
| 最新値カード | 血圧・体重・体組成（BMI/体脂肪/骨格筋/内臓脂肪） | 目標との関係が分からない。ダイエットの進み具合が見えない |
| 推移グラフ | 血圧、体重・体組成 | 有用だが、ダイエット計画（目標線）は健康サポート画面にしかない |
| 表示期間 | 開始日・終了日 | グラフ専用の操作なのに独立した大きなカードになっている |
| ウォッチ記録 | 選択日の歩数・距離・活動エネルギー・心拍・酸素・睡眠（6カード） | 1日単位の集計のみで、週の傾向が分からない。説明文が長い。モバイルでは縦に非常に長い |
| 健康サポート画面 | 減量計画、エネルギー収支、週次レビュー | Homeから進捗が見えず、毎日確認する導線がない |

結論：**「今日どうだったか」「目標に近づいているか」「今週の傾向」**が一目で分からない。

## 2. 設計方針

1. **最初の1画面で今日の状態が分かる**：あいさつ・日付・今日のチェック（体重/血圧/睡眠/歩数目安）を最上部に置く。
2. **ダイエット進捗を主役に**：現在体重・目標・達成率リング・残り kg・目標日まで日数・7日変化・30日推移（計画線つき）。
3. **毎日の運動量と睡眠を週で見る**：今日の歩数/活動エネルギー/運動時間と、直近7日の歩数バー・睡眠ステージ積み上げバー。
4. **エネルギー収支**：今日の摂取 vs 摂取目標、推定総消費。
5. **既存の詳細は残し、下に畳む**：最新値カード・推移グラフはそのまま（ID互換）。表示期間はグラフ区画の小さなツールバーへ。ウォッチ記録の日別詳細は `<details>` に収納。
6. **記録がない値はゼロ扱いしない**：「—」「記録なし」と表示。推定値・目安は明記し、診断ではないことを維持。

## 3. 画面構成（上から順）

```
┌ Today ヘッダー ───────────────────────────┐
│ 10月28日(水) / おはようございます、〇〇さん    │
│ [✓体重] [✓血圧] [✓睡眠 6h27m] [歩数 5,200/8,000] │
└───────────────────────────────────────┘
┌ ダイエット進捗 ──────────┐┌ 今日の活動 ─────────┐
│ ◎達成率リング 74.4kg       ││ 歩数リング / 活動kcal │
│ 目標70.0kg 残り4.4kg       ││ 運動時間 / 距離       │
│ 7日 -0.4kg 目標日まで90日  ││                       │
│ 30日推移 sparkline + 計画線 ││                       │
└───────────────────────────┘└───────────────────────┘
┌ 睡眠（昨夜）┐┌ 心拍 ┐┌ エネルギー収支 ┐
└────────────┘└──────┘└────────────────┘
┌ 直近7日の歩数（棒） ┐┌ 直近7日の睡眠（ステージ積み上げ）┐
┌ からだの記録：最新の血圧・体重・体組成（既存） ┐
┌ 推移グラフ：血圧／体重・体組成（既存）＋表示期間 ┐
▶ ウォッチ・ヘルスケアの日別詳細（既存、折りたたみ）
```

PC（1000px超）は2〜3カラム、モバイルは1カラム（KPIは2列）。

## 4. データの出どころ（新規APIなし）

| 表示 | 取得元 |
|---|---|
| 体重・目標・計画線・7日変化 | `/api/wellness/energy`（`active_plan`, `history`）、`/api/wellness/summary`（`goal_weight_kg`, `weight_change_7d_kg`）※既存の `refreshWellness` が取得済みの値を再利用 |
| 今日の摂取・目標・推定基礎代謝・運動時間 | `/api/wellness/energy` の `current`・`history` と今日の活動記録 |
| 歩数・距離・活動エネルギー・心拍・睡眠 | `/api/apple-health/samples`（直近8日分、1000件ずつページング） |
| 測定済みチェック | `/api/records`（既存の `chartRecords`） |

計算ルール：
- エネルギー収支＝摂取 − 推定基礎代謝 − ウォッチの活動エネルギー。活動エネルギーの記録がない日は基礎代謝のみで今日の値を出し、7日グラフでは表示しない。今日の活動エネルギーは現在までの記録分（途中経過）。
- 記録元が複数ある場合は、件数が最も多い記録元だけを集計（重複加算を避ける）。
- 歩数・距離・活動エネルギーは開始時刻の日（端末のタイムゾーン）に合計。
- 睡眠は「前日18時〜当日18時」に重なる区間をその日の睡眠とし、覚醒・ベッド時間を除外、重複区間は1回だけ数える。
- 達成率＝(開始体重−現在体重)/(開始体重−目標体重)。計画がない場合は直近90日の最初の体重を開始とする。0〜100%に丸めて表示。
- 歩数目標は利用者ごとの健康設定 `step_goal`（初期値 8,000 歩、1,000〜50,000）。Homeの「今日の活動」カード、または健康サポートの健康設定から変更できる。

## 5. 実装

- `web/home.js`：Home専用の描画（純粋な計算関数は Node から単体テスト可能）。
- `web/app.js`：`refreshRecords` の最後で `refreshHome()` を呼ぶ（存在しない場合は何もしない）。
- `web/index.html`：overview セクションを再構成（既存IDは維持）。
- `web/styles.css`：Home用スタイル（ライト/ダークのトークンを利用）。
- `tests/home-dashboard.cjs`：日別集計・睡眠・達成率の回帰テスト。
