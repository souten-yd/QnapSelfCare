# HBF-228T 接続失敗と再試行制御（2026-10-12）

## 確認した事象

利用者環境で約14分間にわたりHBF待ち受け同期が繰り返し失敗。取得した直近ジョブの診断はすべて `stage=connection`、受信RSSIはおよそ -86〜-97 dBm。ESP32の当該接続journalは `open:133`、認証・アプリキー送信・測定履歴取得に進んだ証拠はない。通常API通信は応答し、診断時のWi-Fi RSSIは約 -38 dBm、free heapは約85 KB。監視workerは同期中に停止されるため、その間のwatch由来 `apiConnected=false` だけでWi-Fi障害と断定しない。

接続失敗の根本原因は未確定。弱い電波は候補だが、端末の接続可能状態や他のcentralとの競合、controllerの状態は近距離での比較なしに除外できない。既存キー不一致を示す認証応答は今回の失敗ログにはない。`open` journalの時間はOPENイベント受信を基準にするため、0〜3msを「接続要求後に即失敗」と読み違えない。

## 確定したソフトウェア要因と対策

従来はHBFのdiscovery/connection失敗を成功クールダウンの対象外とし、新しい広告が来るたびに試行回数を1へ戻していた。さらに接続後エラーで設定したburst blockedは、HBFがburst判定を通らないため抑制に効かなかった。電波等の障害が持続すると自動試行が止まらない。

v0.3.38は初回即時、接続前の失敗後は30秒以上待って新しい広告で1回だけ再試行する。2回目の失敗または認証・データ通信・不明な段階の失敗後は5分休止する。休止中に見た広告は消費し、タイマーだけでは再接続しない。5分後に新しい広告が来た時点で次の初回を許可する。無線をリセットしたり再ペアリングしたりする処理は追加しない。

成功後の1時間抑止と測定結果の即時保存は維持。失敗制限はRAMだけであり再起動後も残る成功時刻とは別物。手動同期は制限対象外。

## 検証と次の実機切り分け

連続広告・fingerprint変化・期限経過のみ・キャッシュ広告・段階別エラー・手動成功からの復帰を回帰試験する。既存試験で成功後1時間の再起動越しの抑止、HEM待機/再試行、保存を確認する。模擬試験や配備成功を体組成計との接続成功とは扱わない。

M5GOと体組成計を1〜2mに近づけ、通常の測定または短押しによる通信で、RSSI・OPEN・認証・履歴保存を順に確認する。P表示の再登録は要求しない。改善しなければ同じ状態を再登録なしでUSB経路と比較する。近距離での成功、最後のOTA後の認証、新しい測定の保存は別途実機確認が必要。
